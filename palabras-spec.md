# Palabras — спека для сборки

Приложение для изучения испанских слов. Локальное, бесплатное, без сервера.
Собирается через Claude Code. Референс текущей логики — `palabras.html` (одностраничный прототип, коробки Лейтнера, 66 слов, работает).

---

## 1. Жёсткие ограничения

Их нельзя нарушать, даже если кажется, что «так удобнее»:

- **Никакого бэкенда.** Ни Node-сервера, ни базы, ни аккаунтов, ни авторизации.
- **Никакого build-шага.** Нативные ES-модули, обычный CSS. `git push` → сайт обновился. Никаких npm, Vite, бандлеров, TypeScript-компиляции.
- **Никаких фреймворков.** Ванильный JS. Приложение маленькое, React тут — чистый оверхед и лишний тулчейн.
- **Local-first.** Приложение обязано полностью работать без интернета и без настроенной синхронизации. Синк — опциональная надстройка, а не условие запуска.
- **Один пользователь на устройство.** Никаких профилей и переключения юзеров. Девушка открывает тот же URL — у неё своя изолированная колода в её браузере.

## 2. Хостинг

**GitHub Pages** из публичного репозитория (для бесплатных Pages это нормально — код открыт, данные нет).

Альтернатива, если захочется приватный репозиторий: **Cloudflare Pages** — тоже бесплатно, подключается к приватному репо. Смена хостинга не должна требовать правок в коде.

## 3. Синхронизация между своими устройствами

Через **приватный GitHub Gist** — один JSON-файл `palabras.json`.

Настройка (экран «Настройки»):
1. Пользователь создаёт fine-grained PAT с единственным разрешением **Account permissions → Gists: Read and write**.
2. Вставляет токен и (опционально) ID существующего гиста. Если ID пуст — приложение создаёт новый приватный гист и запоминает ID.
3. Токен и ID хранятся в `localStorage`.

Алгоритм синка:
```
sync():
  1. GET  /gists/{id}          → remote
  2. merge(local, remote)      → merged
  3. записать merged локально
  4. PATCH /gists/{id}         ← merged
  5. сохранить lastSyncAt
```

Слияние — по полю `updated` (ISO-строка) на каждом объекте:
- `words`: по `id`, выигрывает больший `updated`. Удаление — это tombstone (`deleted: true`), а не отсутствие записи, иначе удалённое слово воскреснет с другого устройства.
- `cards`: по ключу `wordId|dir`, выигрывает больший `updated`.
- `settings` и `stats` не синхронизируются вообще — они локальные для устройства.

Когда запускать: при открытии приложения, на `visibilitychange` → visible, и с debounce 10 с после ответов. Нет сети или нет токена — тихо пропустить, никаких модалок с ошибками. Индикатор состояния — одна мелкая строка в настройках («синхронизировано 5 минут назад» / «только локально»).

Конфликты в реальности исключены: один человек, одно устройство в момент времени. Last-write-wins честно достаточен, городить CRDT не надо.

**Важный момент про iOS.** Safari может вычистить IndexedDB у PWA, которым не пользовались несколько недель. Настроенный синк — единственная страховка от потери прогресса. Об этом должна быть прямая строчка в настройках, а не мелкий шрифт.

## 4. Модель данных

```js
{
  v: 2,
  deviceId: "<uuid>",
  words: [
    { id, es, ru, ex, mn, created, updated, deleted }
  ],
  cards: {
    "<wordId>|es": { box: 1, due: "2026-07-28", arch: false, updated },
    "<wordId>|ru": { box: 1, due: "2026-07-28", arch: false, updated }
  },
  settings: { theme: "auto", goal: 20, sync: { gistId, token } },
  stats: { day: "2026-07-28", done: 0 }
}
```

- `dir: "es"` — показываем испанское, вспоминаем русское (узнавание).
- `dir: "ru"` — показываем русское, вспоминаем испанское (воспроизведение).
- `mn` (мнемоника) лежит в `words`, потому что пользователь один. Если когда-нибудь появится общая колода — переносить в `cards`.
- Хранилище: **IndexedDB** (localStorage не переживёт пары тысяч слов и вычищается агрессивнее). Обёртка — свой мини-модуль на 40 строк, библиотеки не нужны.

Стартовая колода — 66 слов из `palabras.html` (массив `SEED`), перенести как `deck.seed.json`. Загружается только при первом запуске.

### Пополнение колоды из репозитория

`deck.seed.json` — это не только стартовая колода, но и постоянный канал пополнения: «дописал слова → `git push` → они появились на всех устройствах».

```json
{
  "version": 7,
  "words": [
    { "id": "llave", "es": "la llave", "ru": "ключ", "ex": "No encuentro las llaves.", "pos": "n" }
  ]
}
```

Правила:
- `id` — стабильный строковый ключ, задаётся руками при добавлении и **никогда не меняется**. Переименование `id` = новое слово + потерянный прогресс по старому.
- При каждом старте приложение читает `deck.seed.json` и добавляет только те `id`, которых нет локально. Новые слова попадают в коробку 1 с `due` = сегодня.
- Существующие слова **не перезаписывать**: пользователь мог поправить перевод или дописать мнемонику, и апдейт колоды не должен это стирать.
- Слово с локальным tombstone (`deleted: true`) не воскрешать.
- `deck.seed.json` в service worker забирать по стратегии **network-first** (или stale-while-revalidate), иначе cache-first отдаст старую копию и пополнение не доедет.

Слова, добавленные прямо в приложении, живут только в локальных данных и синкаются через Gist. В репозиторий они не попадают — это разные каналы, и смешивать их не нужно.

Побочный эффект, о котором стоит помнить: `deck.seed.json` общий для всех, кто открывает сайт. Слова, запушенные в репозиторий, появятся и у второго пользователя. Прогресс, мнемоники и добавленные вручную слова при этом остаются полностью раздельными.

## 5. Движок повторений

Коробки Лейтнера, интервалы **1 / 2 / 4 / 8 / 16 дней**. Плюс шестое состояние — `arch` (архив).

Логика уже реализована в `palabras.html`, перенести без изменений:
- верный ответ → коробка +1, `due` = сегодня + интервал новой коробки;
- ошибка → коробка 1, `due` = сегодня, карточка возвращается в конец текущей сессии;
- архивные карточки исключены из очереди, но подмешиваются примерно 1 на 10 обычных;
- архивная угадана → остаётся в архиве; не угадана → `arch = false`, коробка 2, обратно в оборот;
- архивные повторения не считаются в дневную цель.

### Веса режимов — не пропускать

Разные режимы тренируют разное, и одинаково их засчитывать нельзя: узнать слово среди трёх вариантов много легче, чем вспомнить с нуля. Если все режимы двигают одинаково, слова «выучиваются» фальшиво.

```js
const MAX_BOX = { type: 5, flip: 3, choice: 3, match: 0 };
```

- Верный ответ: `box = min(box + 1, MAX_BOX[mode])`. Если карточка уже выше потолка режима — не двигается, но и не наказывается.
- Ошибка в `type` / `flip` / `choice`: `box = 1`.
- Ошибка в `match`: `box = max(1, box - 1)` — там много промахов пальцем, полный сброс был бы несправедлив.

Следствие: в коробки 4–5 карточка попадает **только** через ввод текста. Одними квизами слово выучить нельзя, и это правильно.

### Выбор режима под карточку

```
коробка 1        → flip или choice   (знакомство, не отбить желание)
коробка 2–3      → choice или type   (случайно, 50/50)
коробка 4–5      → только type
из архива        → type
```

## 6. Режимы

Все четыре — это разные обёртки над одной карточкой. Общий интерфейс: модуль получает карточку и колбэк `onAnswer(correct)`, возвращает DOM-узел. Движок повторений про режимы ничего не знает, кроме имени для `MAX_BOX`.

**`type` — ввод текста (RU→ES).** Уже есть в прототипе. Нормализация: нижний регистр, снятие диакритики, отбрасывание артикля, обрезка пробелов. Расстояние Левенштейна ≤ 1 → «почти, опечатка», засчитывается как верно. На мобильном: `autocapitalize=off`, `autocorrect=off`, `spellcheck=false`, `font-size: 16px` (иначе iOS зумит страницу при фокусе).

**`flip` — карточка с переворотом.** Показывается испанское, кнопка «Показать», затем самооценка «Помнил / Не помнил». Анимация переворота — CSS `transform: rotateY`, 250 мс, обязательно под `prefers-reduced-motion`. На телефоне — свайп влево/вправо как альтернатива кнопкам.

**`choice` — три варианта.** Направление любое. Дистракторы подбирать осмысленно, иначе выбор тривиален:
1. приоритет — та же часть речи (нужно проставить `pos` у слов колоды: `n` / `v` / `adj` / `phrase`);
2. затем — близкие по длине и по первой букве;
3. добор — случайные из той же коробки.
Никогда не брать дистрактор, который является синонимом правильного ответа.

**`match` — сопоставление двух колонок.** Пачка из 6 пар: слева испанские, справа русские, обе колонки перемешаны независимо. Тап по слову слева, затем по слову справа. Верная пара — гаснет; неверная — короткая подсветка и разрыв. Пачка закончилась → следующая. Это разминка в начале сессии (только если набирается ≥6 карточек к повторению), она не двигает коробки вверх.

Структура сессии:
```
[match ×6, если карточек хватает] → основная очередь (режим выбирается по коробке) → экран итога
```

## 7. Дизайн

Направление — **спокойный минимализм**. Не Duolingo: никаких маскотов, конфетти, сердечек, звуков. Тишина, воздух, одна акцентная краска. Единственный яркий момент во всём интерфейсе — момент верного/неверного ответа.

### Токены

```css
:root {
  --bg:      #F7F7F6;   --surface: #FFFFFF;
  --text:    #1A1A19;   --muted:   #6E6E6B;
  --line:    #E4E4E1;   --accent:  #3A5A40;
  --ok:      #4E7A55;   --err:     #A85B52;
  --radius: 10px;
}
[data-theme="dark"] {
  --bg:      #121312;   --surface: #1B1C1B;
  --text:    #EDEDEA;   --muted:   #92938F;
  --line:    #2A2B29;   --accent:  #7FA88A;
  --ok:      #7FA88A;   --err:     #D08B80;
}
```

Тема: `auto` (следует `prefers-color-scheme`) / `light` / `dark`, выбор хранится в настройках, переключатель из трёх позиций. `<meta name="theme-color">` менять вместе с темой, иначе на Android шапка останется от старой.

### Типографика

Одна гарнитура — **Inter** (variable, с локальным фолбэком на системный стек), контраст создаётся весом и размером, а не смешением шрифтов. Цифры — `font-variant-numeric: tabular-nums`.

```
слово на карточке   clamp(32px, 8vw, 52px) / вес 300 / трекинг -0.03em
перевод, ответ      20px / 400
интерфейс           15px / 400–500
подписи, счётчики   12px / 500 / трекинг 0.04em / --muted
```

### Компоновка

Одна колонка по центру, максимум 560px, много вертикального воздуха. Никаких карточек-в-карточках, теней и рамок там, где хватает одной линии `--line`.

Вместо шести плиток коробок — **тонкая горизонтальная шкала** под карточкой: шесть сегментов разной ширины пропорционально числу слов, подпись появляется по тапу. Это единственный «фирменный» элемент, всё остальное вокруг него должно молчать.

### Адаптив

| | Ширина | Что меняется |
|---|---|---|
| Телефон | ≤ 480 | Кнопки действий прижаты к низу экрана (зона большого пальца), учитывать `env(safe-area-inset-bottom)`. Шкала коробок — над кнопками. |
| Планшет | 481–1024 | Колонка 560px по центру, кнопки инлайн под карточкой. В `match` две колонки шире, тапабельность сохраняется. |
| Десктоп | > 1024 | То же, что планшет, плюс горячие клавиши: Enter, Пробел, 1/2/3. |

Минимальная зона тапа 48×48. Никаких действий, доступных только по ховеру. `touch-action: manipulation` на кнопках, чтобы убрать 300 мс задержки. Ландшафтная ориентация на телефоне не должна ломать `match`.

## 8. PWA

- `manifest.webmanifest`: имя, иконки 192/512 (в том числе maskable), `display: standalone`, `theme_color`, `background_color`.
- `sw.js`: cache-first для оболочки (HTML, CSS, JS, шрифты), сеть только для Gist API. Версия кэша в константе, старые кэши чистить в `activate`.
- Шрифт положить в репозиторий, а не тянуть с Google Fonts — иначе офлайн интерфейс поедет.
- Push-уведомления **не делать**: в iOS-PWA они ненадёжны, а напоминалка, которая молчит через раз, хуже её отсутствия.

## 10. Порядок работ

Три этапа. Каждый заканчивается работающим приложением — не начинать следующий, пока предыдущий не задеплоен и не открыт с телефона.

**Этап 1 — переезд.** Логика из `palabras.html` разложена по модулям, IndexedDB, PWA, GitHub Pages. Дизайн пока старый, режим один (`type` + `flip`).
*Готово, когда:* приложение установлено на домашний экран телефона, работает в самолётном режиме, прогресс переживает перезапуск.

**Этап 2 — дизайн.** Токены, две темы, типографика, адаптив, шкала коробок.
*Готово, когда:* обе темы выглядят законченными, на телефоне ничего не требует горизонтального скролла и зума, кнопки достаются большим пальцем.

**Этап 3 — режимы.** `choice`, `match`, веса режимов, структура сессии.
*Готово, когда:* карточка физически не может попасть в коробку 4 иначе как через ввод текста.

Синхронизация через Gist — в конце этапа 1 или отдельным четвёртым шагом. До неё приложение уже полезно на одном устройстве.
