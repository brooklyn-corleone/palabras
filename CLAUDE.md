# Palabras

Приложение для изучения испанских слов. Статический PWA на GitHub Pages, без бэкенда.
Направление обучения: **испанский ↔ русский**.

`palabras-spec.md` — исходная спека: модель данных, движок повторений, дизайн-токены, этапы.
Читать её стоит, но **этот файл главнее**: по ходу работы часть решений изменилась,
и расхождения перечислены ниже.

`reference/` — материалы, из которых всё выросло, приложением не используются и в кэш
не попадают: `palabras.html` — прототип с коробками Лейтнера и нормализацией ответов,
`deck-2026-07-28-66-words.json` — первая колода про дом и быт, снятая при переходе
на украинский и потом на русский. Слова оттуда можно вернуть отдельной темой.

## Чем это отличается от спеки

Спека писалась до старта, эти решения приняты после:

- Язык перевода менялся: русский → украинский (v3) → снова русский (v4). Поле слова — `ru`,
  направление карточки — `"<id>|ru"`. Обе миграции в `state.js` — вызовы `renameDir`.
- **Мнемоник нет.** Поле `mn` в модели данных осталось, но нигде не показывается и не редактируется.
- **Примеров на карточке нет.** Поле `ex` тоже осталось в модели, но не отображается.
- Добавлен режим **`letters`** — собрать слово из букв. Его потолок — коробка 4.
- Добавлен третий раздел — **«Правила»** (`notes.seed.json`): таблицы спряжений, род и число,
  цифры, алфавит. Разложены по группам (`groups` в файле, `group` у правила), внутри раздела
  раскрываются гармошкой. Те же правила иногда сами всплывают между карточками — примерно
  раз в восемь ответов. Прогресс им не начисляется.
- Правило состоит из заголовка и **блоков**: `table`, `list`, `text`. Одно правило может
  смешивать таблицу, перечень исключений и пояснение, а рисуется всё одним кодом
  (`renderBlocks` в `notes.js`) — и в разделе, и в карточке занятия.
- Добавлены **темы колоды** (`cat` у слова, словарь `categories` в `deck.seed.json`) —
  занятие можно собрать по одной теме.
- Добавлена **настройка занятия**: какие слова (к повторению / случайные / выбранные галочками),
  темы, сколько слов, каким форматом. Живёт в памяти: после перезагрузки — обычное повторение.
  Темы и форматы выбираются наборами: `session.cats` и `session.modes` — это Set, пустой
  означает «все» и «авто». Несколько форматов сразу расширяют набор направлений карточек
  (`allowedDirs` в `srs.js`), а каждой карточке достаётся тот из выбранных, что подходит
  её направлению.
- **Цель останавливает занятие**: по достижении показывается экран с выбором
  «продолжить или хватит», а не молча уезжающий счётчик. Число в подписи обрезано по цели —
  после двадцати там «20 / 20», а не «49 / 20».
- Цель считается **за занятие**, а не за день, хотя лежит по-прежнему в `state.stats.done`.
  Обнуляется в `startSession` — то есть и при сборке нового занятия, и при запуске
  приложения. Обнуление по смене даты в `state.js` осталось: приложение с домашнего
  экрана не перезагружается неделями и должно пережить полночь.
- В цель идут **только верные ответы**. Неверная карточка возвращается в очередь и будет
  отвечена ещё раз — считая обе попытки, цель набиралась бы тем быстрее, чем хуже дела.
- Слово можно пометить **«не собирается из букв»** (`noLetters`) прямо на карточке.
  Это жалоба на формат, а не на слово: в колоде и в остальных форматах оно остаётся,
  а режим `letters` его больше не берёт (`modeAllowed` в `srs.js`). Занятие, собранное
  только форматом «Из букв», такие слова не тащит вообще. Снять пометку — на вкладке «Слова».
- Шрифт — **системный стек**, не Inter. Свой файл шрифта ради офлайна пришлось бы класть
  в репозиторий; системный уже на устройстве. Если Inter понадобится, менять `--font` в одном месте.

## Жёсткие правила

Не нарушать, даже если кажется, что так удобнее:

- **Нет build-шага.** Нативные ES-модули, обычный CSS. Никаких npm, Vite, бандлеров, TypeScript.
  `git push` → сайт обновился.
- **Нет зависимостей.** Ни одной внешней библиотеки.
- **Нет фреймворков.** Ванильный JS, ES2020.
- **Нет бэкенда и аккаунтов.** Данные — в IndexedDB. Синхронизация — опциональная, через приватный Gist.
- **Local-first.** Приложение обязано полностью работать офлайн и без настроенного синка.
- Не подключать шрифты и скрипты с CDN — всё лежит в репозитории, иначе офлайн ломается.

## Команды

```bash
# локальный запуск (нужен http://, не file://, иначе не заработают модули и service worker)
python3 -m http.server 8000

# деплой
git push        # GitHub Pages подхватывает main автоматически
```

Сборки нет. Тесты лежат в `tests/srs.test.js` — двадцать с лишним сценариев на коробки,
веса режимов, архив, сборку занятия и пополнение колоды. Запускаются во временной папке:
`node --test` требует `package.json` с `"type": "module"`, а он выглядит как шаг к npm.
Команда запуска — в шапке самого файла. **Трогаешь `srs.js` — прогоняй тесты.**

## Режимы и веса

```js
MAX_BOX = { type: 5, letters: 4, flip: 3, choice: 3, match: 0 }
```

Выученные слова подмешиваются в обычное занятие: примерно одно на десять карточек,
но не больше `MAX_ARCHIVE_MIX` (три) за раз и после применения лимита «сколько слов».
Угадал — остаётся в архиве и в дневную цель не идёт, не угадал — возвращается во вторую коробку.

Смысл: чем больше подсказок даёт режим, тем ниже его потолок. В коробку 5 карточка попадает
**только** через чистый ввод по памяти. `match` — разминка в начале сессии, коробки вверх
не двигает и в цель не идёт.

Выбор режима (`pickMode` в `srs.js`): направление `es` — всегда `flip` или `choice`;
направление `ru` — коробка 1 даёт `choice`/`letters`, коробки 2–3 `letters`/`type`, дальше только `type`.
Из обеих пар `letters` выпадает, если слово помечено `noLetters` — второй режим в паре
есть всегда, поэтому выбирать остаётся из чего.

## Правила по данным

- `id` слова в `deck.seed.json` — стабильный, задаётся руками, **никогда не меняется**.
  Смена `id` = потерянный прогресс.
- Пополнение колоды обновляет **нетронутые** слова (без флага `edited`) и не трогает те,
  которые пользователь правил в приложении. Так опечатка в переводе чинится одним пушем,
  а ручная правка живёт вечно. Следствие: менять поля слова можно **только** через `updateWord`,
  иначе правка останется незамеченной и её затрёт следующее пополнение.
- Исключение из предыдущего пункта — **пометки, а не правки**: `flagged` («проблема»)
  и `noLetters` («не собирается из букв») ставятся своими функциями (`flagWord`, `skipLetters`),
  которые нарочно **не** трогают `edited`. Жалоба не должна замораживать слово: его текст
  всё ещё нужно чинить пушем. Такое поле обязано лежать вне `SEED_FIELDS`, иначе пополнение
  его затрёт.
- Удалённые слова (tombstone `deleted: true`) не воскрешаются.
- Миграции формата — только вперёд, с проверкой поля `v`, и **обязательно с сохранением
  результата**: незакреплённая миграция проигрывается каждый запуск и рано или поздно
  оставляет данные между двумя форматами.
- Никогда не стирать пользовательские данные при апдейте.
- Токен Gist не логировать, не коммитить, не подставлять в примеры.

## Про обновления

`sw.js` вызывает `skipWaiting()`, а `ui.js` перезагружает страницу по `controllerchange`.
Регистрация идёт с `updateViaCache: 'none'`, обновление проверяется на каждый `visibilitychange`,
`deck.seed.json` и `notes.seed.json` тянутся с `cache: 'no-cache'` — и в `fetch`, и при установке.

Все четыре пункта нужны из-за `max-age=600` на GitHub Pages: без них браузер до десяти минут
не замечает ни новый воркер, ни новые данные, а приложение с домашнего экрана — вообще неделями.
Без этого новый воркер стоит в очереди, пока не закроются все вкладки со старым, — а на
телефоне вкладка не закрывается неделями. При этом `deck.seed.json` идёт по сети и приезжает
свежим: получается старый код с новыми данными, и выглядит это как «функция не работает».

**Версию `CACHE` в `sw.js` поднимать при каждом изменении файлов оболочки.** Забыл поднять —
у пользователя останется старая версия, и никакие правки до него не доедут.

## Стиль

Комментарии и коммиты — по-русски. Код и идентификаторы — по-английски.
Функции короткие, без классов там, где хватает замыкания.
Комментарий объясняет «почему так», а не «что делает строка».
Понятность важнее лаконичности: этот код будут читать через полгода и без контекста.
